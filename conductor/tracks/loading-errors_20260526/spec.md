# Specification: Loading & Error States for Story Views

**Track ID:** loading-errors_20260526
**Type:** Feature
**Created:** 2026-05-26
**Status:** Draft

## Summary

Add loading indicators and graceful error/retry handling to the Hacker News story
views, and return proper error responses from the backend, so the app always feels
responsive and never appears broken or blank.

## Context

newApp is a React-based news reader that aggregates top, new, and best Hacker News
stories into a clean reading surface for general web visitors. Two product goals —
**fast, clean reading UX** and **reliability** — depend on the app handling slow or
failed Hacker News API calls gracefully. Today `client/src/App.jsx` fetches all three
feeds on mount with no loading state, replaces the entire app with red text on error,
and shows a basic "No stories available" empty state. The backend
(`api/index.js`) returns a plain `500` string on failure rather than a structured
JSON error.

## User Story

As a reader, I want both loading indicators and graceful error/retry handling, so
that the app always feels responsive and never appears broken.

## Acceptance Criteria

- [ ] A loading skeleton/placeholder shows while stories are being fetched.
- [ ] On fetch failure, a clear error message with a **Retry** button is shown inline (the whole app is not replaced).
- [ ] The backend returns a proper non-200 status with a JSON error body when the Hacker News API fails (not a plain `500` string).
- [ ] A sensible empty state shows if the API returns no stories.

## Dependencies

Depends on existing code (already present, so this track improves rather than blocks on it):

- The existing endpoints `/api/topstories`, `/api/newstories`, `/api/beststories` in `api/index.js`.
- The existing story-listing UI in `client/src/App.jsx` (Top/New/Best sidebar + `renderStories`).

## Out of Scope

- Server-side automatic retries or caching of Hacker News responses.
- Independent loading/error state per tab — the three fetches are treated as one combined state.
- Any visual redesign/restyling of the story list or sidebar beyond adding loading/error/empty UI.
- Adding new API endpoints or changing the story data shape.

## Technical Notes

- Refactor the fetch logic out of `App.jsx` into a custom hook (e.g. `useStories`) that returns `{ data, loading, error, retry }`.
- Use Tailwind-based skeleton placeholders for the loading state.
- Keep the error state inline within the content area (do not replace the entire app), with a Retry action that re-runs the fetch.
- Backend: return appropriate status codes and a JSON error body (e.g. `{ "error": "..." }`) from the story handlers.
