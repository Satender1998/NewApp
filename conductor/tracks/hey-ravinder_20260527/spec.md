# Specification: "hey ravinder" Greeting Endpoint

**Track ID:** hey-ravinder_20260527
**Type:** Feature
**Created:** 2026-05-27
**Status:** Draft

## Summary

Add a new backend endpoint `GET /api/hey-ravinder` that logs `hey ravinder` to the
server console and returns it as a JSON response.

## Context

newApp is a thin Express backend (`api/index.js`) serving the React/Vite client. It
already exposes a simple greeting endpoint `/api/hey` (plain text "hey satender")
implemented as a handler module in `api/lib/hey.js` with a `node:test` unit test.
This track adds a sibling greeting endpoint following the same pattern.

## User Story

As a developer/visitor, I want to hit `/api/hey-ravinder` so that the server logs and
returns a "hey ravinder" greeting, confirming the route works.

## Acceptance Criteria

- [ ] `GET /api/hey-ravinder` returns HTTP 200 with JSON body `{ "message": "hey ravinder" }`
- [ ] The server logs `hey ravinder` to the console (via `console.log`) when the endpoint is hit
- [ ] The handler is implemented as a separate module under `api/lib/` (mirroring `hey.js`)
- [ ] A `node:test` unit test verifies both the console log and the JSON response
- [ ] The endpoint is documented in `conductor/tech-stack.md`'s endpoint list

## Dependencies

None. Follows the existing `hey-endpoint_20260526` pattern but is independent.

## Out of Scope

- Any frontend/client UI changes
- Configurable/dynamic names (the greeting is hardcoded to "ravinder")
- Authentication, rate limiting, or input handling

## Technical Notes

- New handler `heyRavinderHandler` in `api/lib/hey-ravinder.js`: calls
  `console.log("hey ravinder")` then `res.json({ message: "hey ravinder" })`.
- Register `app.get("/api/hey-ravinder", heyRavinderHandler)` in `api/index.js`,
  alongside `/api/hey`.
- Test in `api/lib/hey-ravinder.test.js` stubs `res.json` and asserts the payload;
  spies on `console.log` to assert the log message.
